# Seyarkai — Governed AI Execution Workspace

A hackathon project built for the **Google Cloud AI Builders Cup**.

AI agents (Google ADK + Gemini) execute multi-stage Work Items under human-approved policies, grounded in a freshness-aware knowledge base (Company Brain, on Vertex AI Search), with checkpoint approvals by assigned reviewers. Deployed on Google Cloud Run.

## Stack

| Layer | Technology |
|---|---|
| Backend | Python 3.11, FastAPI, async SQLAlchemy 2, Alembic, PostgreSQL |
| AI Runtime | Google ADK (LlmAgent + Runner), Gemini 2.5 via Vertex AI |
| Tools | MCP servers built with FastMCP (knowledge search, document generation) |
| Knowledge | Vertex AI Search — freshness-aware retrieval with ageing/stale badges |
| Frontend | Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui |
| Database | Cloud SQL (PostgreSQL 16) |
| Deploy | Cloud Run, Secret Manager, Artifact Registry, Cloud Build |
| CI | GitHub Actions (test) + Cloud Build trigger on `main` (build + push) |

## Local Development

### Prerequisites
- Python 3.11, Node.js 22
- PostgreSQL 16 running locally
- `gcloud` CLI authenticated (`gcloud auth application-default login`)

### Backend

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate        # Windows
pip install -r requirements.txt

# copy and fill in values
cp ../.env.example ../.env

alembic upgrade head
uvicorn app.main:app --reload
```

### Frontend

```bash
cd frontend
npm install
# set NEXT_PUBLIC_API_URL in frontend/.env.local
npm run dev
```

### Tests

```bash
cd backend
pytest -m "not live and not integration"
```

## Cloud Deployment

### Build images (Cloud Build)

```bash
gcloud builds submit --config cloudbuild.yaml
```

### Deploy backend

```bash
./deploy/deploy-backend.sh https://seyarkai-frontend-337434518869.us-central1.run.app
```

### Deploy frontend

```bash
./deploy/deploy-frontend.sh
```

> `NEXT_PUBLIC_API_URL` is baked into the frontend image at build time via `--build-arg`.
> Rebuild the image if the backend URL changes.

## CI/CD

- **Tests**: GitHub Actions runs `pytest -m "not live and not integration"` on every push.
- **Build + Push**: Cloud Build trigger fires on every push to `main`, builds both Docker images and pushes them to Artifact Registry.
- Gemini is never called in CI. Live tests use `@pytest.mark.live`.

## Key Concepts

| Concept | Description |
|---|---|
| **Work Item** | A unit of work assigned to an AI agent and human reviewers |
| **Policy** | An ordered set of stages + checkpoints governing how a Work Item executes |
| **Execution** | A live run of a published Policy; streams events via SSE |
| **Checkpoint** | A human approval gate between stages (approve / reject / provide input) |
| **Company Brain** | A Vertex AI Search corpus of company documents with freshness tracking |
| **Artifact** | A document generated by the AI during execution (Google Doc or HTML) |
